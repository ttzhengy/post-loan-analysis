# 组合归因规则库（combination-insights）

被 `scripts/attribution.py` 引用。风险特征表中的 45 项风险大类是**基础指标**；本规则库将多个基础指标按业务机制组合，挖掘**更深层的线索本质**（如"获客激进""准入失守""建档造假"等）。

**用法**：`attribution.py` 读取 features.json，对每条组合规则检查其组成特征是否有命中（metric 非空且超过阈值），按「命中数 / 命中强度」生成深层线索，供报告「分析主题」章节使用。

**重要**：本文件是**规则引擎**，不是写死的主题结论。具体主题由数据驱动生成——命中哪些特征、组合强度如何，取决于当期数据；严禁把本文件的规则名称当作必然结论写死进报告。

---

## 一、规则结构

```json
{
  "rule_id": "C01",
  "name": "获客激进扩张",
  "essence": "机构为冲规模批量获客，准入标准被稀释",
  "members": [1, 2, 3],
  "logic": "零散获客 + 无抵押缓释 + 低评分准入 同时命中 → 获客激进",
  "min_hits": 2,
  "evidence_fields": ["零散客户占比均值", "信用类余额占比均值", "低分段(<600)占比"],
  "controllable": true
}
```

- `members`：组成该线索的风险特征 ID（对应 risk-features-map.md）
- `min_hits`：至少命中几条才触发
- `evidence_fields`：从成员 metric 中提取展示的证据字段

## 三、线索强度计算

```
线索强度 = 命中特征数 / 组成特征数 × 0.6 + 命中特征平均信号值(归一化) × 0.4
```

- 命中特征数占比反映「广度」：特征越多同时命中，机制越可信
- 平均信号值反映「强度」：命中特征的 metric 值（占比/不良率/数量）越大越显著
- 强度 ≥ 0.5 标为「显著线索」，≥ 0.3 标为「一般线索」，否则为「弱信号（不进入主题候选）」

**证据链要求**（对齐《报告模板》A-2 支持证据）：
- 每条线索必须列出命中特征及其关键 metric 值作为证据
- 线索结论须与「不良余额贡献」联动：某线索覆盖客群的不良率 / 不良余额占比显著偏高才算成立
- 仅特征命中但无不良表现差异 → 标注「信号存在、风险差异待验证」

---

## 四、主题生成约束（严禁硬写）

1. 报告「分析主题」只从**当期数据实际触发**的组合线索中选取，不预置固定主题。
2. 每条主题须给出：发现（数据信号）→ 机制（组合逻辑）→ 影响范围（覆盖客群规模 / 不良贡献）。
3. 若当期数据未触发任何组合（全部弱信号），则报告退化为「指标监测式」，如实说明未见强组合信号，不强行拼凑主题。
4. 组合线索名称（如「获客激进扩张」）仅作为分析提示词，报告中须用业务语言展开论证，不得直接照抄规则名当结论。

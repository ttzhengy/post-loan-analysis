# 预览版说明（由 D 验证后补齐实测结论）

## 为什么有预览版

现有 skill 的核心投诉是「不管什么数据，报告主题都一样」。这个问题**无法靠读代码证明已修好**，
只能靠「换一套数据，主题必须变」来验证。所以本次优化强制产出 4 套合成数据集的完整 HTML 报告。

**重要边界**：合成数据只能验证**逻辑正确性**（主题是否随数据变、强度是否可区分、
降级是否生效）。真实数据上的效果，必须用户拿回本地用真实 parquet 跑一遍才成立。
合成数据**不能**替代本地实跑。

## 四套数据的构造意图

| 数据集 | profile | 构造 | 预期主题形态 |
|---|---|---|---|
| `dataset_01` | p1 获客激进与准入失守 | 贷前端特征普遍偏离基线 2–3.4 倍；线索级 lift 2.2–4.5；接续工具用`展期`做缓冲 | 应命中**获客/准入类**线索，标题业务化为「规模冲动下的准入稀释」一类，**不得**出现接续/道德类主题 |
| `dataset_02` | p2 接续滚动与道德风险 | 贷后端特征偏离 2.2–3.6 倍；线索级 lift 偏向客户经理/接续/风险信号未处置；`不良重组`不良率显著高；滚动接续笔数占 18% | 应命中**接续滚动/人员道德**类线索，**不得**出现获客/准入类主题 |
| `dataset_03` | p3 全弱信号 | 全部 45 项特征偏离基线 0.10–0.35，线索 lift 0.6–1.15，不良率 1.0% | **0 条主题**，退化为「指标监测式」并如实说明未见强组合信号 |
| `dataset_04` | p4 缺 cohort | 同 p1 但 `cohort.json` 为空 | 线索可命中，但**最高只能「一般」**，不得出现「显著」，且应标注降级原因 |

## 判定准则（D 的验收口径）

1. `dataset_01.topic_set ≠ dataset_02.topic_set` —— 这是**最关键的一条**，旧版会给出完全相同的 C01/C02/C03
2. `dataset_03` 主题数 = 0，且报告出现「指标监测」形态
3. `dataset_04` 无「显著」级主题
4. 4 份 HTML 均断网可开、均有图表、`data-calc-id` 与验算清单一一对应

## 每份预览报告多了一个「主题生成轨迹」折叠块

**仅预览版包含，正式报告不含。** 内容：
- 每条候选规则的广度分量 / 强度分量 / 最终 strength
- 进主题或淘汰的 `reason`
- 被采纳的钻取假设原文
- 客群校验结果（lift / 样本量 / status）

这个块是给人看的，用来判断「是不是真在动态分析」还是「换个数据照样出同样结果」。

## 复现命令

```bash
python synth/make_synth.py --all --outdir synth       # 生成 4 套数据
python tools/build_preview.py                         # 跑全链路 + 出 4 份 HTML
```
